## 编译和验证

Keil MDK5 / ARMCC5 打开 `Project.uvprojx`，芯片 STM32F103C8，C99、`STM32F10X_MD`、`USE_STDPERIPH_DRIVER` 以及 MicroLIB 已配置。安装工程指定的 STM32F1 设备包后，执行 F7；在本机完成 ARM 编译后再烧录。工程不再引用原模板中缺失且无关的 mycontrol、OLED、TRACE、TIM3_PWM 文件。

本地静态检查与主机回归：

```sh
python tools/check_project.py
python tests/run.py --cc gcc
```

可用 GCC、Clang 或 TinyCC，也可将 `--cc` 替换为编译器完整路径。测试编译生产 C 源码，注入测试外设输入，覆盖 PID、编码器溢出/清距、ADC 故障、巡线状态机、按键和调度。外设替身不能证明电气时序、物理轨迹或停车精度；它不参与固件构建。

## 任务选择

| g_task / RUN_MODE | 行为 |
|---|---|
| 10 | 从 A 朝 B 发车，在第 4 个有效直角特征（A）停车，不再转完弯后继续行驶 45cm |
| 11 | A-B 单边巡线，在第 1 个有效直角特征（B）停车 |
| 1 | 连续巡线调试 |
| 2 | 完成一次转弯后停车 |
| 0 | 直行闭环调试，默认不限距 |
| 3 | 电机停转，观察灰度及推车累计脉冲 |
| 4 | 电机正反转自检 |
| 6 | 同 PWM 采样 2 秒，读 g_trim_sum_l/r 后转到模式 3；不会自动修改 g_trim |
| 20 / 21 | 保留倒车入库 / 侧方停车状态机，未经实车验收 |

PA11 一次有效按下切换 `10 → 11 → 20 → 21 → 10`；PA12 重新启动当前模式。两键采用 30ms 稳定状态和按下沿检测，长按只触发一次。按键接线沿用上传版本，PA11/PA12 是否确实接出按键必须核实；这两个管脚也可能用于 USB。Watch 可以在每次发车前修改 `g_task`，不能在比赛运行中人工干预。

## 标定与已知边界

接线与交接单一致：左 PWM PA0，方向 PA1/PA2；右 PWM PA3，方向 PB1/PB8；编码器 PA6/PA7 与 PB6/PB7；灰度 PB12/13/14 选择通道，PB0 采样；STBY 接 3V3。系统使用 TIM1 产生 1ms 时基，TIM2 PWM、TIM3/4 编码器。时钟按标准库默认 8MHz HSE 倍频至 72MHz，硬件晶振必须相符。

1. 模式 3 观察 `g_dbg[0..7]`，黑线读数小于白底，按实测设置 `g_track_threshold`，有效范围 1..4095。传感器从左到右通道顺序须核实。
2. 推车已知距离得到每厘米脉冲数。默认 `g_pulse_per_cm=71.3` 只是理论值；右轮闭环目标比例 `g_trim` 应按 `右轮脉冲/cm ÷ 左轮脉冲/cm` 结合实测设置，不能从同 PWM 转速比推断。当前距离函数仍使用公共脉冲当量，左右当量差异明显时泊车距离须单独标定。
3. 默认 12cm/s 为低速调试值：理想 4m 直行已需约 33.3s，无法满足整圈 30s，转弯还会耗时。应在完成低速稳定性验证后实测提速；没有宣称已达比赛限时。
4. A/B 到点依赖直角特征，传感器安装位置、刹车惯性会影响车身投影，须按实车调整。失去黑线持续 500ms 或转弯超过 1200ms 会锁定停车，不能作为成功到点。
5. 模式 20/21 的车库前进距离及转向时间仍为未经实测的示例值，不能保证整车入库、不压底线。任务三没有摄像头接口或识别实现，未做虚假补齐。

`g_fault`：0 正常，1 持续丢线，2 转弯超时，3 控制调度落后至少一个完整周期，4 ADC 故障，5 标定参数无效。修复原因后切换任务或按 PA12 重启。ADC 故障需重新初始化时应复位。编码器方向、轮距、场地尺寸、限时与停车投影须按原题及现场口径逐项验证。
